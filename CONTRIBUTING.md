# Contributing to pattern-library

Thank you for your interest in improving the pattern library. This repository collects evidence-led patterns for recurring product and customer insights.

## Before you contribute

- Review the [README](README.md) for the project scope.
- Search existing issues before opening a new one.
- Keep proposals focused on clarity, reusability, and actionable insight for product and customer work.
- Do not include client data, confidential business information, credentials, API keys, or personal information in issues, pull requests, or documentation.

## Contribution guidelines

1. Create a branch from `main`.
2. Make one focused change at a time (new pattern, refinement, or documentation improvement).
3. Ensure patterns are concise, evidence-based, and tied to real outcomes.
4. Run basic checks before opening a pull request:

```bash
git diff --check
```

5. In your pull request, explain:
   - The problem or gap this pattern addresses.
   - The pattern structure and how it should be used.
   - Any examples or references that informed the pattern.

## Design principles

- Prefer clarity and repeatability over cleverness.
- Anchor patterns in observable evidence, not opinion.
- Write for mixed audiences: product, design, data, and engineering.
- Treat patterns as living artifacts that evolve with practice.

## Reporting issues

Use the repository issue templates for bugs and feature requests. For security concerns, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.
